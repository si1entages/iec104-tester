# IEC 60870-5-104 协议符合性修复报告

> 修复日期：2026-09-25 | 范围：`core/protocol/` + `core/engine/` | 测试：**371 passed**、ruff 零告警
> 协作方式：审计定位 → 工程师实现 → QA 独立证伪式验证（两轮）

---

## 一、背景

审计发现协议层与引擎层**并非完整符合 IEC 60870-5-104 标准**，而是"电力 SCADA 常用业务子集"的可用实现。本报告记录已修复的 13 项问题（9 项主修复 + QA 独立验证阶段揪出的 4 项）。

---

## 二、P0 严重（影响与真机互操作）

### 1. 时钟同步 ASDU 多写 7 字节
| | |
|---|---|
| 位置 | `core/protocol/asdu.py` `build_clock_sync` / `build_clock_sync_ack` |
| 根因 | 同一 InformationObject 同时设置 `data=time_tag.to_bytes()` 与 `time_tag=`，`encode()` 两处均写入 |
| 修复前 | **23 字节**（时间被写两遍，第三方设备可能拒收） |
| 修复后 | **16 字节**（标准值），hex 中时标仅出现一次 |
| 影响面 | 主站发送 + 子站确认双向都曾受影响 |

### 2. 组召唤 QOI 与响应 COT 非标
| | 修复前 | 修复后（标准） |
|---|---|---|
| 组召唤 QOI（主站发） | 组号 1-16 | `20 + 组号` = **21-36** |
| 召唤响应 COT（子站回） | 41-63 | **20**（站）/ **21-36**（组） |
| 累计量响应 COT | 走 41+ | **37**（总）/ **38-41**（组 1-4） |
| 主站接收判定 | `cot >= 20`（过宽） | C_IC_NA_1 仅 20/21-36；C_CI_NA_1 仅 37/38-41 |

> 说明：修复前主从站"自洽"故自测互通，但与真机不通——发 QOI=1 属非法值，回 COT=41 在标准中是"第 4 组累计量请求"。
> 同步更新：`webui/static/master.html` 输入范围与提示、`webui/api_contract.md`。

## 三、P1 过程完整性

### 3. 文件传输握手闭环
- 主站收到 `F_FR_NA_1` / `F_SR_NA_1` 时**自动回** `F_FR_NB_1` / `F_SR_NB_1`；收到 `F_LS_NA_1` 回 `F_AF_NA_1`
- 子站 `F_LS` 状态由 0 改为 **1**（最后的节）——原值导致主站永不判定 COMPLETED
- 子站支持文件选择 **qualifier=4**（原静默忽略）
- 结果：完整上传流程可跑通至 COMPLETED 并触发 `_on_file_received`（新增端到端测试）

### 4. P/N 否定确认落到标准位置
- `ASDU` 新增 `pn` 字段（COT **bit6**），encode `(cot & 0x3F) | 0x40`、decode 解析
- 子站 4 处否定确认不再篡改命令数据字节 bit7（该位在单/双/升降命令中是 S/E 选择位，原实现污染了 SBO 语义）
- 主站按 `pn` 判定否定确认

### 5. 复位进程 / 参数命令过程
- 核实标准后确认：`C_RP_NA_1` 为 ACT→ACTCON，**无 ACTTERM** → 修正**主站**判定（原主站错误等待永不到来的 ACTTERM）
- `P_ME_NA/NB/NC` → 回 ACTCON 并记录"已装载"；`P_AC_NA_1` 已装载→ACTCON + **ACTTERM**，未装载→否定确认（pn=1）

## 四、P2 缺失能力补齐

### 6. TypeID 58-64（带 CP56Time2a 的控制命令）
补齐 7 个类型：`C_SC_TA_1`/`C_DC_TA_1`/`C_RC_TA_1`/`C_SE_TA_1`/`C_SE_TB_1`/`C_SE_TC_1`/`C_BO_TA_1`，含 builder、解码注册、子站处理（ACTCON 同类型回显）、主站发送方法。
round-trip 实测：C_SC/DC/RC_TA_1=**17B**，C_SE_TA/TB_1=**19B**，C_SE_TC_1=**21B**，C_BO_TA_1=**20B**。

### 7. COT 42/43/44/45 未知类型/原因/地址应答
- 新增 `ASDU.decode_header()` 容错头解析（TypeID 未知时仍可提取 type_id/COT/CA）
- 子站：未知类型→**COT 42**、未知 COT→**43**、公共地址不匹配→**44**，且**保持连接不中断**
- 主站：优雅记录 + 触发事件，不误判为业务响应

### 8. 定时器与流控对称化
- **t0 归属核实**：t0 是连接建立超时，属**主站**职责 → 新增 `use_t0` 开关（子站传 `False`），删除子站误导性分支
- **t1 覆盖 U 帧**：新增 `on_u_frame_act_sent()`，STOPDT ACT / TESTFR ACT 发送时也启动 t1
- **主站 k 窗口耗尽**：由"直接抛异常"改为**等待至多 t1 再抛**（与子站对称）；文件传输 4 个发送方法同步接入
- **失序策略统一**：按标准（失序应关闭连接）两侧均断链；主站新增 `disconnect()` 区分"断开后重连"与"彻底停止"

### 9. 时标与编码缺陷
- **CP24 时标类型**：编码本就正确（13B 为标准值）；真缺陷在**解码**——TA 类被构造成 `CP56Time2a`，导致 round-trip **13→17 膨胀**。已修，现稳定 13→13
- **M_ME_ND_1**：编码由 12B 改为 **11B**（去品质 QDS，符合"无品质"语义）
- **保护事件**：新增 `ProtectionEvent.to_bytes()`，`M_EP_TA/TB/TC_1`=**15B**、`TD/TE/TF_1`=**19B**，不再抛 TypeError

## 五、QA 独立验证阶段揪出的问题（均已修复）

| 编号 | 问题 | 根因 | 修复 |
|---|---|---|---|
| **Bug A** | 主站把**肯定选择确认**误判为 NACK | "兼容旧非标实现"回退分支用数据字节 bit7 判断，而 SBO 选择命令 S/E=1 | 删除回退，严格取 COT bit6；补反例测试 |
| **Bug B** | 失序断链后**状态机残留 Running**、不触发事件、不重连 | `stop()` 取消 `_connect_loop` 时 `CancelledError` 被吞，跳过 `_on_disconnected` | 重构取消路径也触发回调 + 新增 `disconnect()`；补重连边界测试 |
| **Nit C** | 分析器 COT 名称映射不全（显示 `cot_21`） | 未跟上 COT 标准化 | 补齐 21-36/38-41/42-45 及 58-64 类型名 |
| **Nit D** | 前端 QOI 可输入 17/18/19 → 后端 ValueError | `min/max` 无法表达非连续集合 | 新增 `isValidQoi()` 提交前校验 + 提示 |

## 七、已知遗留（本轮未做，需独立立项或后续迭代）

| 项 | 说明 |
|---|---|
| **TLS / IEC 62351** | 未实现（当前为裸 TCP）。属安全特性开发，非缺陷修复 |
| **冗余 / 双通道** | 未实现。属架构级特性 |
| **非标准 TypeID 编号** | `M_PS_TB_1=71`、`C_TS_NB_1=108`、`P_ME_ND_1=109`、`F_FR_NB_1=128`、`F_SR_NB_1=129` 占用了标准保留号或超出 127 范围 |
| **`wrong_cot` 注入** | 已于 2026-09-26 落地：`SlaveEngine._reply_cot()` 把应答（命令确认/召唤确认·数据·结束/时钟同步确认）的 COT 整体 +1，Web UI「返回错误COT」开关与 `errors.wrong_cot` 配置贯通；自发上送与标准错误应答（42/43/44）不参与注入 |
| **文件传输 F_LS 语义** | 功能已闭环（status=1，主站接受 {1,2}），但该八位组在标准中的严格定义（校验和 CHS 与 QLS 的取舍）建议与目标设备实测核实 |
| **背景扫描** | IEC 104 不适用（仅 101） |
| **参数命令"先删后写"顺序** | 未做设备级验证，建议对真实设备联调时观察 |

## 八、结论

修复后，协议层与引擎层在**常规业务与真机互操作**层面已对齐标准：召唤（站/组/累计量）、时钟同步、遥控选择-执行、参数装载激活、文件传输全流程、否定确认、错误应答（COT 42/43/44）均按标准实现，且主从站行为对称。

**仍未达标的是"型式试验/一致性认证"级别的完整覆盖**——缺 TLS、冗余，以及少数非标准 TypeID 编号。若需用于正式入网检测，建议以本文第七节为输入，对照目标检测机构的用例清单做逐项确认。
