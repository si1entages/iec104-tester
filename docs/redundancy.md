# 冗余双通道（T21）— 模型、配置与切换行为

> 覆盖边界（诚实声明，**请勿宣传为"支持完整冗余标准"**）：
> 本文档描述的是**主站侧双连接主备切换**这一最小可用模型。IEC 60870-5-10
> （或 DL/T 634.510）定义的完整冗余组语义（冗余组管理、地址选址、
> 双通道热备同时活跃、状态机协商等）**未实现**。

## 1. 模型

主站同时维护两条**独立** TCP 连接（主用/备用），分别指向两个冗余前置机：

```
MasterEngine
 ├─ MasterRedundancy（组合子模块，core/engine/master_redundancy.py）
 │   ├─ primary TCPClient ──→ 前置机 A（主用，如 192.168.1.10:2404）
 │   └─ standby TCPClient ──→ 前置机 B（备用，如 192.168.1.11:2404）
 └─ _client ──→ 当前**活动态**客户端（主用故障后指向备用）
```

- **同一时刻只有一条通道处于活动态**收发 I 帧；活动态客户端即
  `engine._client`，引擎全部既有发送/接收/状态机路径无感知地工作在其上。
- **备用通道预连接**：TCP 建立 + STARTDT（U 帧）后保持在线（静默吸收，
  其收到的帧不进引擎协议栈，仅学习去重键），随时可接管。备用通道由其
  自身的重连循环持续恢复预连接（`max_reconnects=0`）。
- 两条通道可各自独立配置 TLS（主用通道经 `MasterEngine` 的
  `ssl_context`/`server_hostname` 构造参数；备用通道当前跟随主用通道的
  TLS 参数，见 §6 局限）。

## 2. 切换触发条件

- **主用通道 TCP 断开**（`on_disconnected` 回调）→ 立即切换。
- **TESTFR/t1 超时**：引擎既有定时器处置对超时执行
  `client.disconnect()`（`master_session.on_timer_expired`），断链同样
  以 `on_disconnected` 呈现 → 走**同一条切换路径**（无独立判定逻辑）。
- 非活动通道断开：仅记 WARNING，由其重连循环自动恢复预连接，**不触发切换**。

## 3. 切换后的链路重建（正确性关键）

切换动作（`MasterRedundancy._failover`）：

1. 引擎先感知断开（状态机离开 Running、DISCONNECTED 事件）；
2. `engine._client` 换为备用通道，活动态标记同步切换；
3. 若备用已预连接 → 立即走既有 `on_tcp_connected` 路径：auto STARTDT
   （`auto_start=False` 时由切换流程显式补发）；
4. **STARTDT CON 使 VS/VR 归零**——这是 `SequenceManager
   .process_rx_u_frame_startdt_con()` 的既有协议行为，因此新链路上的
   I 帧序号从 0 重新开始，与从站侧（STARTDT ACT 同样使其归零）一致；
5. 进入 Running 后自动补发一轮**总召唤**（切换后的数据面重建）；
6. 原主用通道由其重连循环恢复后**自动成为新的备用**（主备角色互换），
   不得抢占活动态。

## 4. 切换窗口去重

- **键 = ASDU 字节摘要**（跳过 6 字节 APCI）：主备链路各自维护发送序号，
  同一数据在两条链路上的 APCI 序号不同，ASDU 字节才是稳定键。仅对
  I 帧生效（U/S 帧不去重）。
- **去重只发生在应用层分发前**（`MasterSession.handle_i_frame` 经
  `is_duplicate_asdu` 门控）：I 帧的序列号消费与确认**永远照常进行**，
  重复仅表现为"不重复入库/不重复上事件"。**传输层绝不丢 I 帧**——丢帧
  会让 VR 失步、触发断链重建，反而放大故障。
- 学习来源：非活动通道静默吸收时记录键；活动通道经门控记录键。两侧
  已见数据在切换窗口（`dedup_window` 秒，默认 5.0）内对齐。
- 原始帧缓冲（rx buffer）、报文录制、历史库记录的是**实际到达的帧**，
  重复帧照录（去重只抑制应用层数据面）。

**去重的局限**：

- 只能识别 **ASDU 字节完全相同**的重复（同 type/IOA/值/COT/时标）。
  带时标值在两条链路上时标不同、或从站重发时 COT 变化 → 视为不同数据。
- 窗口内的**合法重复**（从站按周期重发同一实测值且 ASDU 逐字节相同）
  也会被抑制；依赖每次重复都产生应用层事件的场景需调小 `dedup_window`。
- 窗口外的重复不识别（切换完成后不再去重，除非 ASDU 恰在窗口内）。
- 去重不跨重启持久化（纯内存，进程重启即清零）。

## 5. 配置

`core.config.RedundancyConfig`（`AppConfig.redundancy`，仅主站生效）：

```yaml
redundancy:
  enabled: false           # 启用冗余双通道（默认关闭，行为与单通道一致）
  standby_host: "127.0.0.1"
  standby_port: 2404
  switch_timeout: 2.0      # 切换后等待 STARTDT CON 的超时（秒）
  dedup_window: 5.0        # 切换窗口去重时间窗（秒）
```

- 主用地址/端口沿用既有 `connection.host/port`；
- **配置无效即失败**（构造 `MasterEngine` 时抛 `ValueError`）：
  `standby_host` 为空、`standby_port` 非法、备用地址与主用完全相同——
  与 T20 的失败策略一致，不做静默降级；
- **多站 `StationConfig` 不支持冗余**：多站管理器管理的是子站（Slave）
  站点，冗余是主站侧行为，二者无交集；子站侧的多连接本身即由
  `SlaveEngine.max_connections` 天然支持。

## 6. 未覆盖部分（明确声明）

- **双通道热备同时活跃**：不支持两条链路同时收发/负载分担；
- **IEC 60870-5-10 冗余组语义**：冗余组管理、选址、组状态协商均未实现；
- **备用通道应用层健康探测**：就绪判定仅依赖「TCP 已连接 + STARTDT 已发」，
  不探测应用层可用性；备用通道无 TESTFR 周期保活，前置机空闲超时断开
  备用时由重连循环自动恢复预连接；
- **备用通道独立 TLS 参数**：当前跟随主用通道的 `ssl_context`（指向两个
  不同前置机而证书不同时，需扩展配置，暂未做）；
- **切换期间在途命令的状态**：主用断开瞬间未收到确认的命令（遥控/设点）
  不自动在新链路上重发，由上层（测试脚本/操作员）决定是否重下；
- **切换可观测性**：目前仅结构化日志（切换开始/完成含耗时/失败原因），
  未接入 Web UI 状态面板。
